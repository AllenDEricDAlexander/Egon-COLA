## 核心规则

设计能够满足已批准需求的最小自洽变更面。完整设计真正发生变化的内容；对相邻代码只检查到足以证明兼容性和安全性为止。

不能因为仓库中存在 Controller、Service、DAO、数据库和前端层，就扩张 Spec。只有拟议实现会改变某层的代码、公开或内部契约、数据/Schema 语义、配置、运行时行为或必需测试职责时，该层才属于受影响范围。

读取文件、经由某层调用，或为了证据引用已有契约，本身不会使该层变成受影响层。

## 两个相互独立的分类轴

必须分开判断：

| 分类轴 | 要回答的问题 | 取值 | 影响 |
| --- | --- | --- | --- |
| 复杂度 | 决策风险和交互复杂度有多高？ | `Simple` / `Complex` | 决定分析深度、场景、证据链和图示 |
| 变更面 | 哪些仓库区域真正发生变化？ | `Affected` / `Context-only` / `Unchanged` / `Not applicable` | 决定哪些章节和元素需要详细设计 |

Simple 任务也可能跨多层；Complex 任务也可能只局限于一个子系统。不能用 `Simple` 逃避受影响内容的细节，也不能用 `Complex` 作为重构未受影响层的理由。

## 变更面处置类型

每个实质相关的仓库区域必须且只能选择一种处置类型：

| 处置类型 | 含义 | 必需证据 | Spec 允许的写法 |
| --- | --- | --- | --- |
| `Affected` | 代码、契约、数据/Schema 语义、配置、运行时行为或测试职责发生变化 | 准确目标路径/符号，以及导致变更的需求 | 完整的适用详细设计 |
| `Context-only` | 为证明受影响边界、依赖、调用链、事务、访问路径或兼容不变量而检查，但不修改 | 准确 Caller/Callee/契约/Schema 证据和被验证的不变量 | 只写简洁证据、保持行为和验证 |
| `Unchanged` | 该区域存在于周边系统中，但已批准变更既不修改它，也不需要在那里作出新决策 | 准确已有契约/路径，以及变更为什么止于该区域 | 一条简洁不变记录；禁止目标重设计 |
| `Not applicable` | 该区域或关注点在仓库/任务中不存在 | 不存在或不相关的证据 | 有证据的 `N/A` |

已有 Controller、Service、Schema 或前端只是没有变化时，不能写 `N/A`。`N/A` 表示不适用；`Unchanged` 表示存在相关上下文，但处于本次变更范围之外。

## 影响锥发现

目标设计前先建立变更面：

1. 从用户点名的行为、文件、符号、查询、表、路由、页面或故障开始。
2. 找出预计真正修改的准确实现符号。
3. 向上追踪直接调用者，直到已有输入/输出/错误/事务不变量能够证明无需继续改变外部契约。
4. 向下追踪直接被调用者和状态副作用，直到所有权、持久化、外部效果和失败行为明确。
5. 检查目前证明该行为的测试，以及必须修改或新增的测试。
6. 使用四种处置类型分类所有已检查区域。
7. 在 Spec Header 和变更面矩阵中记录受影响设计章节。
8. 当下一边界语义完全不变，并且可由聚焦回归断言保护时停止扩张。

仓库证据证明所需结果必须改变以下任一内容时，影响锥必须扩张：

- 调用者可见的入参、出参、错误、顺序、分页或时序语义；
- Service 或其他内部契约的签名与不变量；
- 持久化字段、约束、关系、索引、Migration、事务或锁行为；
- 权限、租户、身份、审计、缓存、事件、外部依赖或配置行为；
- 前端路由、字段、状态转换、文案、权限行为或缓存失效；
- 部署、兼容、发布、回滚或运维归属。

满足需求不需要的偶然缺陷或“顺便重构”不能扩张范围。只有实质相关时，才把它记为范围外风险或后续项。

## 不同处置类型的写作深度

### Affected

写清实施所需的准确路径、符号、职责、契约、字段、分支、状态影响、失败、兼容规则和测试。对发生变化的元素执行所有适用的章节专项参考规范。

### Context-only

只写：

- 检查过的准确仓库证据；
- 依赖的已有边界或不变量；
- 为什么无需修改；
- 防止意外变化的聚焦验证。

不得重新陈述 Context-only 区域的完整 API、模型、表定义、页面状态或架构。

### Unchanged

使用类似以下简洁记录：

```text
Scope disposition: Unchanged
Evidence: <准确路径/符号/当前契约>
Preserved invariant: <保持完全一致的内容>
Reason: <受影响路径为什么止于此处>
Verification: <聚焦回归/静态检查，或有证据的不需要>
```

不得在 Unchanged 区域增加目标文件、新字段、新图示、新接口 ID 或实施决策。

### Not applicable

写 `N/A`，并附仓库证据和原因。不能只留占位符或写笼统的“不需要”。

## 章节路由

为了保持 RFC 审核结构，保留所有编号一级章节，但按照变更面矩阵分配深度：

| 章节/区域 | 聚焦写法 |
| --- | --- |
| 摘要、目标、需求、复核 | 始终描述准确请求结果和受限验收 |
| 背景/现有链路 | 只追踪定位变更并证明停止边界所需的链路 |
| 技术上下文 | 只记录约束受影响工作的技术和仓库规则 |
| 架构 | 设计受影响协作与边界；用证据引用周边不变架构，不重画整个系统 |
| 分包/文件树 | 展示准确变更文件和定位它们所需的少量父级/上下文路径；不能输出空的全层骨架 |
| 接口 | 只完整展开新增、删除或实质变化的契约；否则引用已有契约和保持不变量 |
| POJO/模型 | 只完整设计变化/新增的类型、字段、映射或生命周期；不能盘点无关模型 |
| 数据库 | 只完整设计变化的 Schema/数据/约束/索引/事务语义；DAO 查询变更只记录准确访问路径和相关已有索引证据，不复写整表或 ER 模型 |
| 前端 | 只有前端行为变化时才设计页面/组件/状态；已有但不受影响的前端是 `Unchanged`，不是页面重设计任务 |
| 模式/理念 | 只针对受影响变化点考虑模式；不能遍历所有模式或重述全部架构 |
| 测试 | 设计聚焦的行为变更测试，以及证明未受影响契约稳定所需的最小边界回归 |
| 横切/发布 | 只展开实质受影响项；其余记录保持不变量和验证边界 |

条件性详细参考资料也遵循同一规则。接口、数据库、POJO 或前端表面为 `Affected` 时，才加载相应深度规范；`Context-only` 或 `Unchanged` 时，只检查权威当前实现到足以证明记录的不变量为止。

## 范围扩张门禁

发现用户点名范围无法单独实现所需行为时：

1. 记录证据和将新增为 `Affected` 的准确区域。
2. 判断扩张是否会改变公开行为、数据/Schema、权限、所有权、兼容、部署或其他重大决策。
3. 重大扩张必须在设计该区域前停止，给出选项和影响，请用户批准扩大范围。
4. 已批准契约内部的小型、本地、可逆实现细节，可采用符合仓库惯例的推断，并在有影响时记录。

不能静默把 DAO-only 请求变成 Controller/API/前端重设计。仓库证据证明 Service 或契约必须变化时，也不能强行保持 DAO-only；应把冲突交给用户确认。

## DAO-only 完整示例

需求：调整一个已有 DAO 查询过滤条件，不改变 Controller、Service 契约、数据库 Schema 或前端行为。

| 区域/层 | 处置类型 | 证据/不变量 | Spec 写法 |
| --- | --- | --- | --- |
| Controller/API | `Unchanged` | 已有路由、请求、响应和错误契约完全不变 | 引用路由/符号和回归边界；不复写 JSON 契约 |
| Service 接口 | `Unchanged` | 方法签名和业务结果语义完全不变 | 引用符号和保持不变量 |
| Service 实现 | `Context-only` | 已有方法委托 DAO，并依赖修正后的结果集 | 只写相关调用和预期结果语义 |
| DAO/Mapper 查询 | `Affected` | Predicate/Join/Order/Page 逻辑变化 | 完整设计准确符号、SQL 形状、参数/空值规则、结果语义和失败 |
| 数据库 Schema/关系 | `Unchanged` | 已有字段、约束和关系已经足够 | 引用相关 Migration/表/索引证据；没有 Migration 或 ER 重设计 |
| 测试 | `Affected` | 查询回归必须证明包含/排除、边界、顺序和已有调用方行为 | 定义聚焦 DAO/Mapper 测试，并按需增加最小 Service 回归 |
| 前端 | `Unchanged` | 契约和可见状态不变 | 一条有证据的不变记录；不做页面/组件设计 |

详细内容应集中在 DAO/Mapper 方法、SQL Predicate 和绑定、排序/分页、Null/Empty 语义、相关已有访问路径/索引、映射结果、异常行为和聚焦测试。完整 Controller 载荷、页面树、无关 POJO 清单、整表字段定义和不变 ER 图都属于范围违规。

## 复核门禁

出现以下任一情况时返回 `REVISE`：

- 仅因为架构中存在某层就对其进行完整重设计；
- 已存在但不变的层被误写为 `N/A`；
- `Context-only` 或 `Unchanged` 行引入目标文件、契约、字段、页面、Schema 或抽象；
- 详细章节包含不在 `Affected` 行中的元素；
- 因任务标记为 Simple 而省略受影响元素的完整适用设计；
- 仓库证据证明范围必须扩张，但 Spec 静默扩张或静默维持不可实现的狭窄范围；
- 测试没有同时证明变化行为和声明的不变边界。
